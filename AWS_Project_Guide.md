# AWS Customer Churn Prediction and Analytics Architecture

## 1. Cloud Storage & Organization (Amazon S3)
- **Service**: Amazon S3
- **Purpose**: Store raw, processed, and output data.
- **Structure**: Create a single S3 bucket (e.g., `telecom-churn-project-[your-name]`) with three main folders:
  - `s3://telecom-churn-project/raw-data/` - For the original uploaded CSV dataset.
  - `s3://telecom-churn-project/processed-data/` - For cleaned and preprocessed datasets ready for ML.
  - `s3://telecom-churn-project/outputs/` - For ML model outputs, evaluation metrics, and query results.

## 2. Automated Processing & Validation (AWS Lambda & CloudWatch)
- **Service**: AWS Lambda & Amazon S3 Event Notifications
- **Purpose**: Automatically detect new file uploads and trigger basic validation.
- **Workflow**:
  - Configure the S3 bucket to send an event notification to a Lambda function whenever a new object is created in the `raw-data/` folder.
  - The Lambda function reads the first few rows of the CSV, checks for expected columns, logs the validation status to **Amazon CloudWatch**, and can move the file to an `invalid-data/` folder if it fails validation.

## 3. Exploratory Data Analysis & Machine Learning (Amazon SageMaker)
- **Service**: Amazon SageMaker (Notebook Instances or SageMaker Studio)
- **Purpose**: Perform EDA, visualizations, preprocessing, and model training.
- **Workflow**:
  - Connect your SageMaker notebook to your S3 bucket.
  - Load the raw data into a Pandas DataFrame.
  - Perform EDA (handling missing values, identifying incorrect types).
  - Produce 4+ visualizations (using Matplotlib/Seaborn).
  - Preprocess the data (encoding categoricals, scaling).
  - Train at least two classification models (e.g., Logistic Regression, Random Forest, or XGBoost) to predict the `churned` label.
  - Evaluate and compare using metrics like Accuracy, Precision, Recall, and F1-Score.
  - Save the preprocessed data back to the `processed-data/` S3 folder.

## 4. SQL-Based Analytics (Amazon Athena & AWS Glue)
- **Service**: Amazon Athena & AWS Glue Data Catalog
- **Purpose**: Perform SQL queries on the processed data directly in S3.
- **Workflow**:
  - Use an AWS Glue Crawler to scan the `processed-data/` folder and create a table schema in the AWS Glue Data Catalog.
  - Open Amazon Athena and run at least five analytical SQL queries on the table (e.g., churn rate by operator, average recharge gap for churned vs non-churned).

## 5. Security & Cost Optimization
- **Security (IAM)**: Create specific IAM roles with the Principle of Least Privilege. Only grant SageMaker and Lambda access to the specific S3 bucket.
- **Cost**: Use AWS Free Tier resources. Stick to `t2.micro` or `t3.medium` instances for SageMaker. Set up AWS Budgets to alert you if costs exceed $1. Always turn off SageMaker instances when not in use!

## Step-by-Step Implementation Guide

### Phase 1: Setup and Storage
1. Log in to your AWS Management Console.
2. Go to **S3** and create a new bucket. Ensure it is private (Block all public access).
3. Inside the bucket, create three folders: `raw/`, `processed/`, and `outputs/`.
4. Upload your generated `lk_telecom_synthetic_100k.csv` into the `raw/` folder.

### Phase 2: Automation (Lambda)
1. Go to **AWS Lambda** and create a new Python 3.x function.
2. Assign it an IAM Role with basic Lambda execution permissions and S3 Read/Write access to your bucket.
3. Write a simple Python script in Lambda to read the uploaded S3 file using the `boto3` library and print a success message or row count.
4. Go back to your S3 bucket, click **Properties** > **Event notifications**, and set it to trigger your Lambda function on `All object create events` in the `raw/` prefix.
5. Check **CloudWatch Logs** to see the logs generated by your Lambda function.

### Phase 3: Data Science & ML (SageMaker)
1. Go to **Amazon SageMaker** > **Notebook instances**.
2. Create a notebook instance (use `ml.t2.medium` or `ml.t3.medium` to stay within or close to Free Tier).
3. Assign an IAM role with access to S3.
4. Once running, open JupyterLab and create a new notebook.
5. Use `boto3` and `pandas` to read the CSV from `s3://your-bucket/raw/lk_telecom_synthetic_100k.csv`.
6. Write your Python code for EDA, visualizations, preprocessing, and model training (scikit-learn or xgboost).
7. Save the cleaned dataframe back to S3 using `df.to_csv('s3://your-bucket/processed/cleaned_data.csv', index=False)`.
8. **CRITICAL:** Stop your notebook instance when you are done working to avoid unexpected charges.

### Phase 4: SQL Queries (Athena)
1. Go to **AWS Athena**.
2. Set up a query result location in Settings (point it to your `outputs/` folder in S3).
3. Run a `CREATE EXTERNAL TABLE` statement to define your processed data schema, or use AWS Glue Crawler to do it automatically.
4. Run your 5 analytical queries.

### Phase 5: Documentation
1. Gather your Python notebook, SQL queries, and screenshots of your S3 structure, Lambda logs, and Athena queries.
2. Draw an architecture diagram showing S3, Lambda, CloudWatch, SageMaker, and Athena (you can use draw.io or lucidchart).
3. Compile everything into your 6-8 page Technical Report.
